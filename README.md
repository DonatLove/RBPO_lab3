# Лабораторная работа № 3 — вариант 15

REST API «Бюро находок» на Spring Boot 3, Java 17 и PostgreSQL. Проект развивает лабораторную работу № 2: CRUD-ресурсы сохраняются в реляционной БД, а бизнес-операции меняют связанные сущности в транзакциях.

## Предметная модель

- **User** (`users`) — пользователь, подавший заявление.
- **FoundItem** (`found_items`) — найденный предмет со статусами `AVAILABLE`, `RESERVED`, `HANDED_OVER`.
- **LossReport** (`loss_reports`) — заявление пользователя о пропаже: `OPEN`, `MATCHED`, `CLOSED`, `CLOSED_UNMATCHED`.
- **ItemClaim** (`item_claims`) — претензия, связывающая заявление и найденный предмет: `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `HANDED_OVER`.
- **HandoverRecord** (`handover_records`) — акт передачи по претензии.

Связи: один пользователь может иметь несколько заявлений; заявление и найденный предмет могут участвовать в претензиях; на одну претензию допускается не более одного акта передачи. В схеме БД определены внешние ключи, `NOT NULL`, проверки непустых строк, допустимых статусов и уникальность пары «заявление + предмет». Приложение подключается под отдельной ролью PostgreSQL с ограниченными правами.

## Бизнес-операции

Все пять операций доступны через отдельные POST-эндпоинты под `/api/business`:

1. `POST /api/business/claims/{claimId}/approve` — одобрить претензию. Проверяются статус претензии, доступность предмета, состояние заявления и совпадение категорий; меняются три сущности.
2. `POST /api/business/claims/{claimId}/reject` — отклонить претензию только в состоянии `PENDING`.
3. `POST /api/business/claims/{claimId}/cancel` — отменить `PENDING` или `APPROVED`; при отмене одобренной претензии предмет освобождается, заявление снова открывается.
4. `POST /api/business/claims/{claimId}/handover` — завершить передачу только для одобренной претензии; создаётся/подтверждается акт, меняются статусы претензии, предмета и заявления.
5. `POST /api/business/loss-reports/{lossReportId}/close-without-match` — закрыть открытое заявление без совпадения и отклонить связанные ожидающие претензии.

Операции используют транзакции и блокировки строк для изменяемых объектов. Для сущностей применяется оптимистическая версия (`@Version`), а ошибки состояния и ограничения БД преобразуются в HTTP-ошибки.

## Запуск без Docker (Windows)

Docker Desktop **не требуется**. Нужен установленный локально PostgreSQL и Java 17 или новее. Если PostgreSQL ещё не установлен, установите PostgreSQL для Windows; можно использовать pgAdmin, который обычно поставляется вместе с ним.

### 1. Создайте базу данных и отдельного пользователя

В pgAdmin подключитесь к служебной базе `postgres` под администратором PostgreSQL и создайте базу данных:

```sql
CREATE DATABASE lost_and_found;
```

Если база уже существует, повторять команду не нужно. В той же служебной базе `postgres` откройте Query Tool и выполните `sql/03-create-app-role.sql`, предварительно заменив пароль-заглушку на собственный. Роль `lost_found_app` создаётся один раз.

### 2. Создайте таблицы и тестовые данные

В pgAdmin подключитесь к базе `lost_and_found` под администратором и выполните скрипты в таком порядке:

1. `sql/01-schema.sql` — создаёт таблицы, связи и ограничения.
2. `sql/04-grant-app-permissions.sql` — выдаёт приложению ограниченные права.
3. `sql/02-sample-data.sql` — добавляет демонстрационные записи. Выполняйте только на пустой тестовой базе.

Скрипт с тестовыми данными рассчитан на пустую базу. Если записи с такими же идентификаторами уже есть, используйте новую тестовую базу.

### 3. Запустите приложение

Укажите переменные окружения для процесса приложения. Пример для PowerShell (подставьте пароль, заданный при создании роли):

```powershell
$env:DB_URL = "jdbc:postgresql://localhost:5432/lost_and_found"
$env:DB_USERNAME = "lost_found_app"
$env:DB_PASSWORD = "ВАШ_ПАРОЛЬ"
```

Затем в IntelliJ IDEA запустите `org.example.Main` или выполните Maven goal `spring-boot:run`. Если Maven установлен в PATH, можно использовать:

```powershell
mvn test
mvn spring-boot:run
```

Приложение доступно по адресу `http://localhost:8080`. При запуске Hibernate проверяет структуру существующей БД (`ddl-auto: validate`), но не создаёт таблицы автоматически: перед запуском нужно выполнить SQL-скрипты.

## REST API и Postman

CRUD-ресурсы:

- `/api/users`
- `/api/found-items`
- `/api/loss-reports` (создание требует `applicantId` как query-параметр)
- `/api/item-claims` (создание требует `lossReportId` и `foundItemId`)
- `/api/handover-records` (создание требует `itemClaimId`)

Коллекция для импорта: `postman/Lost and Found API.postman_collection.json`. Окружение: `postman/Local.postman_environment.json`. Импортируйте оба файла в Postman, выберите окружение **Lost and Found - Local**. Коллекция включает CRUD для каждой сущности, пять бизнес-операций и последовательный сценарий из 17 запросов с переменными ID. Запросы сценария нужно выполнять по порядку.

OpenAPI-спецификация находится в `postman/specs/lost-and-found.openapi.yaml`.

## Тесты

Тесты используют H2 в режиме совместимости с PostgreSQL и проверяют основной сценарий бизнес-операций, отклонение операции при несовпадающих категориях без изменения данных и статический endpoint:

```powershell
mvn test
```

Для проверки реальной PostgreSQL используйте локальную БД и параметры окружения из шага 3. Не коммитьте `.env` и реальные пароли в Git.
